Case study · Powerhouse

The engine behind Powerhouse's open-source operations platform

Since December 2023 we've been part of Powerhouse's core engineering team, working on the document engine, the GraphQL API and the cloud console.

The challenge

Powerhouse lets organisations run their operations as shared documents. Every change is stored as an operation, so many contributors can edit the same documents and every step stays auditable. That needs a fast document engine, a secure API, and hosting customers can rely on.

How it works

  1. Connectthe editor people work in
  2. SwitchboardGraphQL API with auth and roles
  3. Document engineoperations, queues, cache
  4. StoragePostgres via Prisma, Redis

What we built

  • Storage and caching for the document engine: Prisma storage, a document cache, and operation queues with in-memory and Redis backends.
  • Switchboard, the GraphQL API: authentication and role checks, protected mutations, health checks and structured logging.
  • Sign-in with Renown, Powerhouse's decentralised identity, covered by end-to-end tests.
  • The Vetra cloud console: one-click add-ons for document AI, a document archive, a 3D model viewer and workflows, plus automatic app deployment.
